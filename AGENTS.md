# dadan-dijital — Agent Instructions

## Project Overview

`dadan-dijital` is a pnpm monorepo (Turborepo) with a NestJS API and a Next.js web frontend. Read this file before starting any task. It applies to every agent session in this repository.

## Monorepo Structure

```
apps/
  api/     → @dadan/api   NestJS backend (Bun runtime)
  web/     → @dadan/web   Next.js App Router frontend
packages/
  db/      → @dadan/db    Prisma schema + migrations + client
  config/  → @dadan/config Shared ESLint/TS config
  storage/ → @dadan/storage File storage utilities
  types/   → @dadan/types  Shared TypeScript types
  utils/   → @dadan/utils  Shared utility functions
```

## Technology Stack

| Layer       | Technology                                       |
| ----------- | ------------------------------------------------ |
| API Runtime | NestJS 11 · Bun runtime · Express adapter        |
| Database    | PostgreSQL · Prisma v7 · PrismaPg driver adapter |
| Auth        | @nestjs/jwt + Guards                             |
| Validation  | class-validator + class-transformer              |
| Caching     | Redis · BullMQ                                   |
| Frontend    | Next.js App Router · TanStack Query v5           |
| Monorepo    | pnpm@9.15.4 · Turborepo                          |
| Node        | >=22 <23                                         |

## Build & Test Commands

```bash
# Root-level (runs all packages via Turborepo)
pnpm build              # Build everything
pnpm dev                # Start all dev servers
pnpm test               # Run all tests
pnpm typecheck          # Type-check all packages
pnpm lint               # Lint all packages

# API-specific
pnpm --filter @dadan/api test          # Unit tests (Jest)
pnpm --filter @dadan/api test:e2e      # E2E tests
pnpm --filter @dadan/api typecheck     # Type-check API only

# Database
pnpm db:migrate         # Run Prisma migrations (all envs)
pnpm db:generate        # Regenerate Prisma client
pnpm db:seed            # Seed the database
```

## Architecture Conventions

### API (`apps/api/src/`)

- **Feature-module architecture**: each domain is a NestJS module under `src/<feature>/`
- **Thin controllers**: extract all business logic to services; controllers only parse input and call one service
- **Repository pattern**: database access goes through repository classes, not directly in services
- **Single PrismaClient**: instantiated once in `DbContext` (`packages/db`), injected via DI — never create a new `PrismaClient` in a service
- **Guards over middleware** for auth: use `@UseGuards(JwtAuthGuard)` not raw middleware
- **DTOs everywhere**: validate all incoming data with `class-validator` + `ValidationPipe`

### Web (`apps/web/`)

- **Feature-based structure**: `features/{domain}/api/ + hooks/ + types/ + index.ts`
- **Server components** fetch reads via feature `fetch*` functions
- **Client components** use `useMutation` for writes; invalidate queries (not `router.refresh`)
- Shared code lives in `shared/lib/`, `shared/components/`, `shared/providers/`

## Explicit Off-Limits

- **Never commit secrets** — all credentials go in `.env` (gitignored)
- **Never edit `packages/db/src/generated/`** — auto-generated by Prisma
- **Never create a second `PrismaClient` instance** — always inject `DbContext`
- **Never use `SELECT *` via `findMany()` on large tables** — always specify `select` fields
- **Never use offset pagination on large tables** — use keyset/cursor pagination instead
- **Never hardcode base URLs** — use `@nestjs/config` + environment variables
